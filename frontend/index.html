PROBLEM & MOTIVATION

Clouds block more than half of usable LISS-IV coverage

Cloud cover is the single largest source of data loss in optical Earth observation. Reconstructing what's hidden — without inventing false detail — is the core challenge this platform addresses.

Avg. cloud cover, Indian monsoon scenes35–60%
LISS-IV revisit cycle5 days
Usable scenes lost to cloud, Jun–Sep~42%
Avg. delay to next clear acquisition10–15 days

Why this matters for ISRO operations

Mission planners can't simply "wait for clear skies" — crop-stress windows, flood peaks, and disaster response timelines don't pause for weather. A reconstructed estimate delivered same-day is operationally more valuable than a clean image delivered two revisit-cycles late. This platform is built to slot into that decision window, not to replace ground-truth acquisition.

Agriculture monitoring

Crop-health indices need continuous time series. A single missed acquisition during a pest outbreak or irrigation decision window can mean acting a week too late.

Disaster management

Floods and cyclones are themselves cloud-generating events — the moments responders need imagery most are exactly when optical sensors are most occluded.

National EO infrastructure

Every reconstructed scene is one less re-tasking request competing for satellite time — lowering the operational cost of maintaining continuous national coverage.

PROCESSING PIPELINE

From raw swath to cloud-free output

Six stages, each independently inspectable. The pipeline is built so a failed detection or a low-confidence mask is visible before it ever reaches reconstruction.

01

Satellite image ingest

Raw LISS-IV multispectral scene is ingested with metadata — band configuration, acquisition geometry, and sensor calibration intact.

INPUT: .tif, 4-band MX
02

Cloud detection

A classifier scans the scene to flag cloud-affected regions, distinguishing cloud from haze, snow, and bright bare soil.

MODEL: Vision Transformer
03

Cloud segmentation

Pixel-precise boundaries are drawn around every detected cloud region, separating thin cirrus from dense cumulus for adaptive handling.

MODEL: DeepLabV3+
04

Cloud mask generation

Segmentation output is converted into a binary occlusion mask — the exact region the generative model is permitted to repaint.

OUTPUT: binary mask, 5.6m/px
05

Generative AI reconstruction

Masked regions are reconstructed using GAN, diffusion, or inpainting networks conditioned on the unmasked surrounding terrain.

MODELS: Pix2Pix · LaMa · Diffusion
06

Cloud-free output

A composited, full-resolution scene is returned with confidence metadata flagging which pixels are observed versus reconstructed.

OUTPUT: cloud-free .tif + confidence map

Diffusion: denoising instead of guessing in one shot

Rather than generating the missing region in a single forward pass, a diffusion model starts from noise inside the masked area and removes it gradually, at each step conditioning on the surrounding unmasked pixels. The result tends to be more stable on large, irregular cloud masks where GAN-based inpainting can produce visible seams.
